# Solana dApp Store submission

The checklist for publishing the Thetis field app (`apps/field`, package `dev.thetis.field`) to
the Solana dApp Store. The requirements come from docs.solanamobile.com, "Submit a new app",
read on 23 November 2026:

- a release-key-signed APK that supports `arm64-v8a` (debug-signed builds are rejected);
- a 512×512 icon, a 1200×600 banner and 4–8 screenshots;
- a public website, with terms and privacy pages served over HTTPS;
- a publisher wallet holding a little SOL;
- KYC for the publisher;
- after submission, review takes about 3–4 business days, and the dApp must be approved before
  it can be added to the store.

The script, `apps/field/store/render.mjs`, draws the art from the field app's brand
(`apps/field/src/theme.ts` and the THETIS wordmark in `src/components/Frame.tsx`): the rail-dark
ground, Archivo SemiBold from the app's own font package, and the oxide-green rule. It uses the
`sharp` that ships with Next.js in `apps/web`. Rerun it after any brand change and commit the
PNGs.

Screenshots show the real app against devnet, signed in, so they come from the release build on
a phone. Good candidates: Home with the "Signing as" card, an intake with evidence attached, the
issue review with the signed text, a handover waiting for the second signature, and a confirmed
outcome with its explorer link.

## Release build

### The upload key (outside the repo)

The upload keystore and its password never enter the repo, a log or a commit:

- keystore: `~/.config/thetis/android/thetis-upload.jks`
- alias: `thetis-upload`
- password: the file `~/.config/thetis/android/thetis-upload.password`

The build reads their locations, not their contents, from Gradle properties or environment
variables with these names. Put them in `~/.gradle/gradle.properties` (outside the repo) once:

```properties
THETIS_UPLOAD_STORE_FILE=/home/<you>/.config/thetis/android/thetis-upload.jks
THETIS_UPLOAD_KEY_ALIAS=thetis-upload
THETIS_UPLOAD_PASSWORD_FILE=/home/<you>/.config/thetis/android/thetis-upload.password
```

The Gradle build reads the password from that file at build time and uses it for both the
keystore and the key. The config plugin `apps/field/plugins/release-signing.js` writes this into
the generated `android/app/build.gradle`; `android/` is generated by prebuild and never committed.
If any of the three values is missing, packaging a release fails with a message naming them, so
a release is never debug-signed or unsigned. Debug builds keep the debug key.

Keep a backup of the keystore and its password somewhere other than this machine. The dApp Store
ties later updates to the same signing key.

### Steps

1. Set the `EXPO_PUBLIC_*` values the release bundle bakes in (`apps/field/src/config.ts`):
   `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`,
   `EXPO_PUBLIC_THETIS_PROGRAM` and `EXPO_PUBLIC_NETWORK=devnet`, in `apps/field/.env` or the
   shell. They must be addresses a phone can reach, not `localhost` (step 6).
2. Generate the native project:
   `cd apps/field && npx expo prebuild --clean --platform android`
3. Build: `cd android && ./gradlew assembleRelease`. The APK is
   `android/app/build/outputs/apk/release/app-release.apk`. The default build includes
   `arm64-v8a` with the other ABIs; `-PreactNativeArchitectures=arm64-v8a` builds only that one,
   which is smaller and faster.
4. Check it:
   - signed with the upload key, not the debug key:
     `$ANDROID_HOME/build-tools/<version>/apksigner verify --print-certs app-release.apk`
     shows the upload certificate, never `CN=Android Debug`;
   - carries `arm64-v8a`: `unzip -l app-release.apk | grep lib/arm64-v8a/`.
5. Install on each phone: `adb install -r app-release.apk`. A phone that has the development
   build must uninstall it first, because the debug and upload keys differ.

## Publisher wallet

The publisher portal pays for publishing from a wallet the publisher controls. Use a dedicated
wallet (not a demo party's wallet), fund it with a little SOL, and connect it on
publish.solanamobile.com when creating the publisher profile. Its keys stay with the owner.

## Submission

On publish.solanamobile.com: create the app with the name "Thetis field", upload the release
APK, the icon, the banner and the screenshots, and give the website, terms and privacy URLs from
step 3. Then submit for review, which takes about 3–4 business days. The task is done when the
release APK installs on both phones and the submission shows as in review.
